# 交付规范（需求分析报告 · 全组必读）

本目录是各组员交付任务的统一位置。**一人一个文件夹，只动自己的文件夹。**

## 目录结构

文件夹命名：**`编号-模块名-姓名`**（编号 1~4 见下表，姓名用真实姓名），如 `1-账户管理-张三`。

```
docs/交付/
  README.md                    ← 本文件（组长维护）
  1-账户管理-钟标/              ← 参考样例：账户管理模块完整交付（用户注册、用户登录，v2 视觉规范样板）
    gen_figures.py              ← 一次生成本模块全部 7 张图（改图走脚本，不手改 .drawio；脚本放自己文件夹里）
    用户注册.md                 ← 一个用例一个 md：功能描述 + 逻辑分析与建模
    用户登录.md
    images/                    ← 本人的所有图片（PNG + drawio 源文件一起提交）
      账户管理模块用例图.png / .drawio
      用户注册_活动图.png / .drawio
      用户注册_类模型图.png / .drawio
      用户注册_协作图.png / .drawio
  2-相册管理-姓名/
  3-照片管理-姓名/
  4-类别与评论-姓名/
```

| 编号 | 模块 | 文件夹 | 负责用例 |
|------|------|--------|----------|
| 1 | 账户管理 | `1-账户管理-姓名/` | 用户注册、用户登录 |
| 2 | 相册管理 | `2-相册管理-姓名/` | 创建相册、修改相册 |
| 3 | 照片管理 | `3-照片管理-姓名/` | 上传图片、浏览照片 |
| 4 | 类别与评论 | `4-类别与评论-姓名/` | 相册类别管理、对照片评论 |

## 每个用例的 md 写什么

照 `1-账户管理-钟标/用户登录.md` 的结构来（这是已完成的完整交付样例），两大部分：

1. **功能描述**：用例描述（六段式：用例名称、参与者、前置条件、基本流程、扩展流程、后置条件）→ 用例图（模块级，同一模块两个用例共用一张）→ 活动图。每幅图后面必须配文字说明。
2. **逻辑分析与建模**：类模型图（边界/控制/实体三类）→ 协作图（消息按用例执行顺序编号）。同样每图配说明。

## 画图流程（各自本机完成，v2 流程）

1. 本机安装 draw.io 桌面版（ https://www.drawio.com/ ）；没有安装也能先出图，见第 3 步的应急渲染。
2. 参照参考样例 `1-账户管理-钟标/gen_figures.py` 写自己的脚本：**样式统一从 `tools/figstyle.py` 取**，脚本只写坐标和文字；脚本放在自己的交付文件夹里。
   - 脚本需要拿到项目根目录：`ROOT = Path(__file__).resolve().parents[3]`，再 `sys.path.insert(0, str(ROOT / "tools"))`。
   - 色板、字号、线宽、类框、标签、折线都用 `fs.*`，不要自己另写一套 `FONT/BOX` 常量。
3. 生成并导出 PNG（以下命令都在**项目根目录**执行，`<模块>` 换成自己的文件夹，如 `1-账户管理-钟标`）：
   ```
   python "docs/交付/<模块>/gen_figures.py"          # 生成 images/*.drawio
   drawio -x -f png --scale 2 -o "docs/交付/<模块>/images/xxx.png" "docs/交付/<模块>/images/xxx.drawio"
   ```
   本机没有 draw.io 时，用应急渲染器（几何与 .drawio 一致）：
   ```
   python tools/render_drawio.py "docs/交付/<模块>/images"
   ```
4. 统一后处理，并看它打印的"内容宽 / 宽高比 / 满宽等效字号"：
   ```
   python tools/postprocess_png.py "docs/交付/<模块>/images"
   ```
   不达标就回去改版面（**不许缩字号**，见 `docs/绘图规范.md` 第 3 节）。
5. **导出后逐张目检**：无穿框、无压字、无贴边、文字完整、四周边距一致。

## 视觉与尺寸要点（详见 `docs/绘图规范.md` v2）

- 颜色只表达分类：主色 `#2F5D8A`、浅主色 `#E9F0F8`、容器 `#F5F8FB`、异常 `#B4532A`（配虚线），全组只用规范里那 7 个色值。
- 字号统一：正文 14、连线标签 12、类名 14 粗体；**内容宽不超上限**（用例 600 / 活动 660 / 类模型 760 / 协作 700），保证满宽插入 Word 后正文 ≥ 8pt。
- 同类图元尺寸统一：用例椭圆 160×52、参与者小人 30×60（保持原图形）、对象框 150×50、类框宽 210 高度自适应。
- 每张图必须能由脚本一键重建；`.drawio` 与 `.png` 同步提交。

## 命名约定

- 交付文件夹：`编号-模块名-姓名`，编号 1~4 按上表，姓名为真实姓名。
- 图片文件名不含图编号（如 `用户登录_活动图.png`）；图编号（图 2-x）由组长整合排版时统一添加，不要烤进图片。
- `.drawio` 源文件与 PNG 同名，一起提交，方便他人后续修改。
- md 中引用图片一律用相对路径，这样在 GitHub 上能直接渲染。写法示例（放在代码块里防转义）：

  ```
  ![用户登录_活动图](images/用户登录_活动图.png)
  ```

## Git 协作流程

1. 仓库已建在 GitHub 上：`sure-660322/electronic-photo-album-system`（**公开仓库**，选公开是为了用上 GitHub 的协作与自动化功能），组员已加为 collaborator。
2. 每人拉取后创建自己的分支，分支名：`成员X-模块名`（如 `成员B-账户管理`）。
3. 在自己的分支上只提交 `docs/交付/自己的文件夹/` 下的内容；公共文件（本 README、`AGENTS.md`、`docs/需求分析/`、`docs/绘图规范.md`、`tools/`、`docs/图稿/`）由组长统一维护，**不要改**。
4. 完成后向 `main` 发 Pull Request，组长对照下方自查清单 review，通过后合并。
5. 合并后组长统一整合进报告 Word 模板、统一图编号。

## 提交前自查清单

- [ ] 用例描述六段式齐全，与 `docs/需求分析/02_用例描述初稿.md` 口径一致（如有修改要说明理由）
- [ ] 每个用例：活动图 1 张；每个模块：用例图 1 张；每个用例：类模型图 + 协作图各 1 张

- [ ] 视觉符合 v2：色值不超过规范第 2.1 节 7 个；正文 ≥ 8pt；内容宽不超上限；同类图元尺寸一致；四周边距一致
- [ ] 每幅图后面有文字说明（画了什么 + 为什么这样设计），不允许只贴图
- [ ] PNG 已逐张目检：无穿框、无压字、文字完整、无贴边
- [ ] `.drawio` 源文件已一并提交，PNG 可由脚本重新生成
- [ ] 图片引用为相对路径，GitHub 上能正常显示
